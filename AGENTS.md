## Правила разработки (SPEC §20)

1. Начинай с `docs/DECISIONS.md` — фиксируй каждое техническое решение с обоснованием.
2. **Не начинай Фазу 1, пока не закрыта Фаза 0.** Будильник — сердце продукта.
   Текущий статус Фазы 0 — см. ADR-007.
3. Пиши тесты на денежную логику до реализации.
4. Вся денежная логика — только на сервере. Клиент не решает, списывать ли.
5. Каждый PR — одна фича. Не смешивать рефакторинг с фичами.
6. Если фича не описана в SPEC — не делай её. Пиши в `BACKLOG.md` и спрашивай.
7. Если требование SPEC противоречит правилам сторов или закону — останавливайся и сообщай,
   не изобретай обход.

## Жёсткие инварианты

Нарушение любого из них — это баг, даже если код работает.

- Деньги — всегда в центах (integer), никогда float (§3.3).
- Время — всегда UTC на сервере; локальная зона живёт в `profile.timezone` (§3.3).
- Окно испытания отсчитывает **сервер**, не клиент (§4.2). Смена системного времени на устройстве
  не должна ни на что влиять.
- Денежные операции идемпотентны — idempotency key на каждой (§3.3).
- Доли распределения не хардкодятся в клиенте — приходят с сервера (§8.2).
- Подписка RISE+ продаётся **только** через StoreKit / Google Play Billing. Продажа подписки через
  Stripe = бан в App Store (§8.4). Stripe — исключительно для денежных ставок.
- Видео по умолчанию не покидает устройство (§4.4).
- Никакой бизнес-логики в компонентах (§3.3).

## Запрещённая лексика в UI и метаданных сторов (§14.2)

Не использовать: «ставка», «выиграй», «джекпот», «казино», «bet».
Использовать: «на кону», «сервисный сбор», «челлендж», «награда».

Также запрещено в коде: вывод наград в реальные деньги, прямой перевод средств между
пользователями, крипто-награды, розыгрыши с платным участием.
