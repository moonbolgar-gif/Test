# RISE — мобильное приложение (демо)

Демонстрационная сборка по [`../../docs/SPEC.md`](../../docs/SPEC.md). Экраны настоящие,
данные — имитация. См. [ADR-012 и ADR-013](../../docs/DECISIONS.md).

## Запуск

```bash
npm install          # из корня репозитория
npm start            # или: npm run start -w @rise/mobile
```

Дальше — установить на телефон **Expo Go** и отсканировать QR-код из терминала
(Android — камерой в самом Expo Go, iOS — системной камерой). Телефон и компьютер должны быть
в одной сети Wi-Fi; если сеть не пускает, помогает `npm start -- --tunnel`.

Собирать dev-client не нужно (ADR-013) — это верно ровно до появления нативного модуля будильника.

```bash
npm run android      # нативная сборка, когда она понадобится
npm run ios
```

Два сценария для показа:

1. **Быстрый:** Дом → «Промотать до утра» → испытание → Победа → Поделиться.
2. **Настоящий:** Дом → «Проверить будильник (1 минута)» → заблокировать телефон → через минуту
   приходит уведомление и звонит будильник → испытание с записью видео.

## Как работает будильник

Звук нарастает с 40% до 100% за 15 секунд (§6.10), играет в цикле, вибрация идёт паттерном.
Звучит даже в беззвучном режиме — иначе будильник бесполезен. Экран не гаснет, кнопка «назад»
заблокирована: испытание можно только пройти или провалить.

Пока приложение свёрнуто, будит серия из 8 уведомлений с интервалом 30 секунд (§4.1, подход A).
При возвращении в приложение испытание открывается немедленно.

## Подсветка лица

У фронтальной камеры iPhone нет вспышки, поэтому источником света работает экран: лаймовый фон
§6.10, белый ореол вокруг кружка и поднятая до максимума яркость. Ореол даёт блик в глазах,
из-за которого лицо читается даже в темноте. Прежняя яркость возвращается при выходе с экрана.

## Чего в демо нет

Это не недоделки, а сознательно отложенное — всё перечисленное требует Фазы 0 или бэкенда.

- **Срабатывание при выгруженном приложении** (§4.1). Если смахнуть RISE из списка приложений,
  будильник не зазвонит. Это главный риск проекта и содержание Фазы 0: нужен `RiseAlarmModule`
  на Kotlin и Swift, который в Expo Go существовать не может.
- **Композитинг видео** (§4.3). Логотип, счётчик и подпись видны поверх видео в интерфейсе, но
  не вплавлены в файл — в Stories уйдёт чистая запись без оверлеев.
- **Списание денег** (§8). Суммы показываются, Stripe не вызывается.
- **Покупка RISE+** (§8.4). Только через StoreKit / Google Play Billing, в демо заглушка.
- **Бэкенд.** Данные живут в памяти и сбрасываются при перезапуске.
- **Онбординг** (§6.2), **выбор друзей** (§6.7), **настройки** (§6.19), **авторизация** (§6.3).

## Структура

```
src/design/      токены §5.1–5.3, типографика, шрифты
src/components/  базовые компоненты §5.4
src/features/    бизнес-логика по доменам (испытания §6.11)
src/screens/     экраны §6
src/lib/         состояние, форматирование, имитация сервера
src/app/         навигация §6.0
```

Граница, которую держим ради будущей замены моков: экраны не считают деньги и не отсчитывают
время сами — за это отвечает `src/lib/demoServer.ts`, единственный модуль, который заменится
на реальный API-клиент.
