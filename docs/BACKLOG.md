## Готово к работе (не требует физических устройств)

Это то, чем можно занять время, пока Фаза 0 упирается в устройства (см. ADR-007).
Порядок — по убыванию пользы.

- [ ] **Спайк 4 — Stripe.** `SetupIntent` (`usage: off_session`) + off-session `PaymentIntent`,
      включая 3DS. Тестовые карты из §13.1: `4242…` (успех), `4000000000000002` (отказ),
      `4000002500003155` (требует 3DS). Целиком серверный, устройства не нужны.
- [ ] **Схема БД + RLS.** SQL из §9 в `supabase/migrations/`. Обязательное условие §9: прямых
      insert/update в `stakes` и `ledger_entries` с клиента быть не должно — только SECURITY DEFINER.
- [ ] **Тесты денежной логики до реализации** (§20.3): распределение сумм и округление центов,
      расчёт поинтов с множителем ×1.5, границы стрика при смене суток и часового пояса.
- [ ] **Проверка совместимости библиотек с New Architecture** (см. ADR-003): `react-native-vision-camera` v4,
      `react-native-sensors`, `react-native-reanimated` v3, `react-native-mmkv`.
- [ ] **Замена `ffmpeg-kit-react-native`.** Апстрим-проект архивирован и снят с публикации.
      Варианты: форк с самостоятельной сборкой бинарей, либо сразу нативный композитинг
      (`AVMutableVideoComposition` / `MediaCodec`+OpenGL) — SPEC §4.3 допускает оба пути.
      Влияет на срок Фазы 3 и на цель «экспорт ≤ 3 сек».
- [ ] **Договор с эко-фондом** (§6.15). До подписания формулировки в UI — только «направляем
      средства на посадку деревьев», с учётом обязательств. Гринвошинг = юридический риск.

## Отложено в Фазу 2+ (из SPEC §2.2 — НЕ строить в MVP)

- Hold / преавторизация средств
- Многодневные челленджи (7/14/25 дней)
- Streak Freeze (платная заморозка стрика)
- Баннерная реклама
- Реальные партнёрские интеграции (в MVP только заглушки «скоро»)
- Розыгрыши / лотереи / билеты
- Глобальный лидерборд (в MVP только друзья)
- Внутренняя лента незнакомцев
- Чат в команде (в MVP только лента активности)
- Трекинг сна, анализ храпа
- Web-версия (см. ADR-004)
- Верификация прохождения испытания другом (§15) — в MVP не решаем
- Членство более чем в одной команде (§7.7 — в MVP ровно одна)
- Доступ к адресной книге (§6.7 — в MVP только инвайт-ссылки)

## Открытые вопросы к владельцу продукта

- **Deferred deep linking** (§7.7): инвайт-ссылка должна доводить нового пользователя до команды
  через установку приложения. Named в SPEC как «напр. Branch» — нужен выбор сервиса и бюджет.
- **Выбор аналитики** (§3.1): PostHog или Amplitude — решение не зафиксировано.
- **Push-инфраструктура** (§3.1): Supabase Edge Function или OneSignal — решение не зафиксировано.
- **RevenueCat** (§3.1) рекомендован, но не обязателен — подтвердить, т.к. влияет на Фазу 6.
