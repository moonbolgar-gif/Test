## 0. TL;DR ДЛЯ АГЕНТА

Построй кроссплатформенное мобильное приложение-будильник с геймификацией, социальным слоем и добровольной денежной ставкой.

**Ядро продукта в одном предложении:** пользователь ставит будильник, утром выполняет мини-испытание (пока пишется видео-кружок), получает стрик и шеринг-карточку для Stories; по желанию ставит на кон реальные деньги — проспал, деньги списываются и распределяются на благотворительность / платформу / фонд наград.

**Три главных технических риска, которые решаются ПЕРВЫМИ:**
1. Надёжное срабатывание будильника на iOS при закрытом приложении (раздел 4.1) — **блокирующий риск**.
2. Списание денег без присутствия пользователя (Stripe off-session) + правила App Store (раздел 8).
3. Запись видео + наложение оверлея + экспорт 9:16 (раздел 4.3).

**Язык интерфейса MVP:** русский (все строки — через i18n, en как второй словарь, но переводить не обязательно на MVP).

## 1. ПРОДУКТ: ЧТО МЫ СТРОИМ

### 1.1. Позиционирование

**RISE — «Wake up. Or pay up.»**
Будильник, который невозможно проспать, потому что на кону твой стрик, твои друзья и (по желанию) твои деньги.

### 1.2. Целевая аудитория

- 18–35 лет, активные пользователи TikTok / Instagram Stories / Telegram.
- Люди, которые «не могут встать» и уже пробовали обычные будильники.
- Вторичная: компании друзей, которые вместе встают рано (спорт, работа, учёба).

### 1.3. Ключевые ценности продукта (в порядке приоритета)

1. **Работающий будильник.** Если он хоть раз не сработает — пользователь удаляет приложение. Надёжность > всё остальное.
2. **Виральность наружу.** Видео-кружок в Stories = бесплатный рост. Это единственный масштабируемый канал привлечения.
3. **Удержание через стрик и команду.** Социальное давление держит лучше силы воли.
4. **Монетизация.** Подписка RISE+ ($1.99) + доля от списаний + сервисный сбор.

### 1.4. Три «температуры» пользователя

| Тип | Что делает | Как монетизируется |
|---|---|---|
| Холодный | Бесплатный будильник, стрик, кружки, команда | Никак (актив для виральности) |
| Тёплый | Оформляет RISE+ | $1.99/мес или $14.99/год |
| Горячий | Ставит деньги на себя / спорит с друзьями | Доля от списаний + сервисный сбор |

**Правило:** деньги никогда не являются барьером входа. Весь социальный и игровой функционал доступен бесплатно.

## 3. ТЕХНИЧЕСКИЙ СТЕК И АРХИТЕКТУРА

### 3.1. Рекомендуемый стек

**Мобильный клиент: React Native (bare workflow, без Expo Go)**
- React Native 0.76+ с New Architecture (Fabric/TurboModules) включённой.
- TypeScript строгий режим (`strict: true`).
- Expo Modules допускаются через `expo-modules-core` + prebuild, но **не Expo Go** — нужны кастомные нативные модули для будильника.
- Навигация: `react-navigation` v7 (native-stack + bottom-tabs).
- Состояние: `zustand` (простое) + `@tanstack/react-query` (серверные данные).
- Анимации: `react-native-reanimated` v3 + `react-native-gesture-handler`.
- Хранилище: `react-native-mmkv` (быстрое локальное).

> **Альтернатива:** Flutter. Если команда сильнее во Flutter — допустимо, экосистема будильников там зрелее (`android_alarm_manager_plus`, `flutter_local_notifications`). Решение принимает техлид в Фазе 0. Но **не смешивать**.

**Нативные модули (писать самим):**
- `RiseAlarmModule` (Android: Kotlin, iOS: Swift) — планирование и срабатывание будильника.
- `RiseVideoModule` — композитинг оверлея на видео и экспорт 9:16.

**Бэкенд: Supabase (Postgres + Auth + Storage + Edge Functions)**
- Auth: Apple Sign In, Google Sign In, email OTP.
- Postgres с Row Level Security (RLS) — обязательно на всех таблицах.
- Edge Functions (Deno) для: Stripe webhooks, начисление наград, верификация подписок, cron-задачи.
- Storage: приватный бакет для видео (если пользователь решил загрузить), публичный для аватаров.

> **Альтернатива:** NestJS + Postgres + Redis на любом VPS. Дороже в поддержке, но полный контроль. Для MVP рекомендую Supabase — быстрее в 2–3 раза.

**Платежи:**
- Денежные ставки (реальные деньги) → **Stripe** (`SetupIntent` + off-session `PaymentIntent`).
- Подписка RISE+ → **StoreKit 2 (iOS) / Google Play Billing (Android)**. Обязательно, см. 8.4.
- Библиотека для подписок: `react-native-purchases` (RevenueCat) — сильно упрощает валидацию, кросс-платформенное состояние, аналитику. Рекомендую.

**Инфраструктура:**
- Push: Firebase Cloud Messaging (Android) + APNs (iOS), через Supabase Edge Function или OneSignal.
- Аналитика: PostHog или Amplitude (события из раздела 12).
- Крэши: Sentry.
- CI/CD: EAS Build или Fastlane + GitHub Actions.

### 3.3. Принципы кода

- **Никакой бизнес-логики в компонентах.** Компоненты — только отрисовка + вызов хуков.
- Вся денежная логика — **только на сервере**. Клиент никогда не решает, списывать ли деньги.
- Время — **всегда UTC на сервере**, локальная зона хранится в профиле пользователя.
- Все деньги — **в центах (integer)**, никогда не float.
- Все побочные эффекты денежных операций — **идемпотентны** (idempotency key на каждой операции).

## 4. КРИТИЧЕСКИЕ ТЕХНИЧЕСКИЕ ЗАДАЧИ (решать в Фазе 0)

### 4.1. ⚠️ НАДЁЖНЫЙ БУДИЛЬНИК — ГЛАВНЫЙ РИСК ПРОЕКТА

Это **самая сложная часть приложения**. Если она не работает — продукта нет.

#### Android (проще)

Использовать связку:
- `AlarmManager.setExactAndAllowWhileIdle()` или `setAlarmClock()` (последний показывает иконку будильника в статус-баре и имеет наивысший приоритет, обходит Doze).
- Разрешение `SCHEDULE_EXACT_ALARM` (Android 12+) — запрашивать явно с объяснением.
- При срабатывании — `BroadcastReceiver` → запуск **Foreground Service** с `MediaPlayer` (звук в цикле, игнорируя режим «без звука», через `AudioManager.STREAM_ALARM`).
- `Notification` с `fullScreenIntent` для показа экрана поверх lock-screen. Требуется `USE_FULL_SCREEN_INTENT`.
- Флаги активности: `FLAG_SHOW_WHEN_LOCKED`, `FLAG_TURN_SCREEN_ON`, `FLAG_KEEP_SCREEN_ON`.
- Перепланирование будильников после `BOOT_COMPLETED`.
- Запрос на отключение battery optimization для приложения (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`), с внятным объяснением зачем.

#### iOS (сложно — здесь основная опасность)

iOS **не даёт** приложению произвольно запускать звук в фоне по таймеру. Работающие подходы:

**Подход A (рекомендуемый для MVP): цепочка локальных уведомлений с кастомным звуком**
- `UNNotificationRequest` с `UNNotificationSound(named:)` — кастомный звук до 30 сек, файл в бандле (формат: `.caf`, `.wav`, `.aiff`).
- Планировать **серию из 20–30 уведомлений** с интервалом 30 секунд, чтобы имитировать непрерывный звон (лимит iOS — 64 запланированных уведомления на приложение, учитывать это).
- `interruptionLevel = .timeSensitive` — пробивает Focus/Do Not Disturb (не требует особого entitlement).
- При тапе на уведомление — открывается приложение на экране испытания.
- Все уведомления серии отменяются, как только пользователь открыл приложение и начал испытание.

**Подход B (максимальная надёжность, требует одобрения Apple): Critical Alerts**
- `UNNotificationSound.criticalSoundNamed()` + `interruptionLevel = .critical`.
- Пробивает беззвучный режим и Do Not Disturb, звучит на полной громкости.
- **Требует специального entitlement** от Apple (`com.apple.developer.usernotifications.critical-alerts`) — подаётся заявка с обоснованием. Для будильника шанс одобрения средний; подавать заявку **в первую неделю разработки**, т.к. рассмотрение занимает недели.

**Подход C (используют Alarmy и подобные): фоновая аудиосессия**
- `AVAudioSession` с категорией `.playback` и `UIBackgroundModes: audio`.
- Приложение проигрывает беззвучный/почти беззвучный трек, оставаясь живым в фоне, и в нужный момент включает громкий звук.
- **Риски:** повышенный расход батареи; Apple может отклонить при ревью, если сочтёт использование background audio нецелевым. Нужна честная формулировка в App Review Notes.

**Решение для MVP:** реализовать **A + C** (A как база, C как усилитель, включается опционально настройкой «Режим максимальной надёжности»), параллельно подать заявку на B.

**Обязательные требования вне зависимости от подхода:**
- Экран «проверить будильник» в онбординге: пользователь ставит тестовый будильник на +1 минуту и убеждается, что всё звонит.
- Экран диагностики: показывать статус всех разрешений (уведомления, точные будильники, оптимизация батареи, Focus) и вести пользователя за руку, если что-то не выдано.
- Резервный механизм: если приложение не смогло гарантировать звук — честно предупредить пользователя в интерфейсе, а не молчать.

**Definition of Done для Фазы 0:** будильник срабатывает 20 раз подряд на 5 реальных устройствах (2 iPhone разных поколений, 3 Android разных вендоров, обязательно Xiaomi/Huawei — у них агрессивный киллинг фоновых процессов) при закрытом приложении, заблокированном экране и включённом энергосбережении.

### 4.2. Окно подъёма и защита от обмана

- **Окно испытания: 5 минут** с момента срабатывания будильника.
- Отсчёт ведётся **на сервере** (клиент присылает `alarm_run_id` и время начала; сервер валидирует).
- Если пользователь не завершил испытание за 5 минут → провал.
- «Отложить» (snooze) — **отсутствует по умолчанию**. Это принципиально: нельзя отложить, можно только выполнить испытание. (Можно добавить опциональный «мягкий режим» в настройках для бесплатных пользователей — 1 snooze на 5 минут, но по умолчанию выключен.)
- Защита: смена системного времени не влияет — всё считается по серверному времени.
- Защита: нельзя удалить будильник в течение 30 минут до его срабатывания, если на нём стоят деньги (иначе пользователь просто удалит будильник, чтобы не платить). Показать объяснение.

### 4.3. Видео-кружок и шеринг-карточка

**Запись:**
- Библиотека: `react-native-vision-camera` v4.
- Фронтальная камера, разрешение 720×720 (квадрат), 30fps, без звука (по умолчанию; звук — опция в настройках).
- Запись стартует **автоматически** при открытии экрана испытания, если включена настройка «Авто-запись».
- Максимальная длина: 60 секунд (или до завершения испытания — что раньше).
- Файл сохраняется **локально**, в приватную директорию приложения. **Не загружается на сервер без явного действия пользователя.**

**Композитинг шеринг-карточки (после победы):**
- Формат: 1080×1920 (9:16), H.264, ≤ 15 сек (обрезать по последним 15 секундам записи, чтобы попасть в лимит Stories).
- Слои поверх видео:
  - Тёмный градиент сверху и снизу (читаемость).
  - Логотип RISE (верх-лево, 12% ширины).
  - Крупный счётчик стрика по центру-низу: `47` + подпись `DAY STREAK 🔥`.
  - Хук-подпись внизу: `я победил будильник 💪 / а ты сможешь?`
  - Время подъёма мелким шрифтом.
- Реализация: `ffmpeg-kit-react-native` (drawtext/overlay) **или** нативный композитинг (`AVMutableVideoComposition` на iOS, `MediaCodec`+`OpenGL` на Android). ffmpeg проще, нативный быстрее — начать с ffmpeg, оптимизировать при необходимости.
- Время экспорта: **цель ≤ 3 секунды**. Показывать прогресс-индикатор.

**Шеринг:**
- Только через системный share sheet (`react-native-share`).
- **Прямой автопостинг в TikTok/Instagram технически невозможен** — не обещать его в UI.
- Дополнительно: `Share to TikTok SDK` (открывает редактор TikTok с уже загруженным видео) — приятный бонус, если успеваем.
- В шеринг добавляется реферальная ссылка на приложение (в текст, не в видео).

### 4.4. Приватность видео

- Видео **по умолчанию не покидает устройство**.
- Явно сообщить об этом на экране записи: «🔒 Видео остаётся у тебя, пока ты не решишь поделиться».
- Автоудаление локальных видео старше 30 дней (настраивается).
- Если пользователь младше 18 — дополнительных ограничений в MVP нет, но в ToS зафиксировать возрастной ценз 18+ (из-за денежной механики).

### 6.11. Виджеты испытаний

**A. Графический ключ ×2**
- Показывается **эталонный узор** (мелкая сетка 3×3 с подсвеченными точками) — его надо повторить.
- Ниже — интерактивная сетка 3×3, узлы 18pt, при попадании — увеличение ×1.5 и haptic.
- Линии рисуются SVG между пройденными узлами.
- Проверка при отпускании пальца: совпадает — засчитан 1 из 2, генерируется новый узор; не совпадает — toast «✗ Не тот узор», узор перегенерируется.
- Узоры — из пула предустановленных (5–7 точек), рандомно.
- Прогресс: `1/2`.

**B. 3 примера подряд**
- Пример вида `7 × 8 = ?`, множители 4–11.
- 4 варианта ответа (1 верный + 3 близких), кнопки крупные.
- Неверный ответ → красная подсветка кнопки + haptic error, пример **не меняется**, попытка снова.
- Верный → следующий пример. Прогресс-полоски `▬▬▬` сверху.

**C. Тряхни телефон ×20**
- Датчик: `react-native-sensors` / DeviceMotion, порог суммы модулей ускорения > 32, дебаунс 250 мс.
- Крупный счётчик `0/20`, haptic на каждую засчитанную тряску.
- Резервная кнопка «Тряхнуть» (для симулятора/DEV) — **в проде скрыть**.

**Общее для всех:** по достижении цели — немедленно останавливается звук, останавливается запись видео, вызывается `POST /alarm-runs/{id}/complete`, переход на Win.

## 7. БИЗНЕС-ЛОГИКА

### 7.1. Жизненный цикл срабатывания будильника (`alarm_run`)

```
scheduled → ringing → in_challenge → completed | failed | expired
```

| Статус | Когда | Действия |
|---|---|---|
| `scheduled` | Будильник создан/запланирован | Записать в БД, запланировать локальные уведомления |
| `ringing` | Сработал | Старт 5-мин окна (сервер), старт звука, старт записи |
| `in_challenge` | Пользователь открыл испытание | Отменить оставшиеся уведомления серии |
| `completed` | Испытание пройдено ≤ 5 мин | Стрик +1, поинты, деревья, награды; денег не списывать |
| `failed` | «Сдаюсь» или окно истекло | Стрик = 0; при денежном режиме — списание |
| `expired` | Пользователь вообще не открыл приложение | То же, что failed |

**Важно:** переход в `completed` инициирует клиент, но **сервер обязан валидировать**:
- `now <= ringing_at + 5min` (по серверному времени)
- статус был `ringing` или `in_challenge`
- нет дублирующего завершения (idempotency)

### 7.2. Правила стрика

- Стрик +1 за каждое `completed` срабатывание, но **не более +1 в календарный день** (по часовому поясу пользователя).
- Стрик обнуляется при `failed`/`expired`.
- Если в день нет запланированного будильника — стрик **не рвётся** (не наказываем за выходные без будильника).
- Личный рекорд (`best_streak`) обновляется при превышении.
- «Consistency» = completed / (completed + failed) за последние 30 дней, в процентах.

### 7.3. Поинты и лидерборд

| Действие | Поинты |
|---|---|
| Подъём вовремя | +10 |
| Шеринг кружка | +5 (макс 1 раз/день) |
| Стрик кратен 7 | +20 |
| Победа в командном споре | +15 |
| RISE+ | **множитель ×1.5 на всё** |

- Лидерборд считается за скользящие 7 дней, сбрасывается по понедельникам 00:00 (в TZ пользователя).
- Показываются только друзья (пользователи, состоящие с тобой в одной команде или добавленные по инвайту).

### 7.4. Маскот и эволюция

| Стадия | Условие (стрик) | Доступно |
|---|---|---|
| 😴 Соня | 0–2 | всем |
| 🙂 Просыпающийся | 3–6 | всем |
| 🦊 Бодрый | 7–20 | **только RISE+** (у free — остаётся на стадии 2) |
| 🔥 Огненный | 21–59 | только RISE+ |
| 👑 Король утра | 60+ | только RISE+ |

- У бесплатных маскот виден, но не эволюционирует выше стадии 2 — при достижении условия показывается тизер «Твой маскот готов эволюционировать → RISE+».
- При обнулении стрика маскот **откатывается на стадию назад**, не в самое начало (мягкость).

### 7.5. Деревья (импакт)

- **1 дерево за каждые 10 успешных подъёмов.**
- RISE+ — ×2 (1 дерево за 5 подъёмов).
- Сервисный сбор с денежных операций также идёт в фонд посадки (учитывается отдельно в `impact_ledger`).
- Счётчик сообщества — сумма по всем пользователям + вклад от сборов (обновляется раз в час через cron).

### 7.6. Ваучеры

- Источники: победа в командном споре, стрик-вехи (7/30 дней), партнёрские кампании (позже).
- Атрибуты: бренд, номинал (в центах), код, статус (`issued` / `redeemed` / `exchanged` / `expired`), срок действия 12 мес.
- Действия: `Использовать у партнёра` (раскрыть код + пометить `redeemed`), `Обменять на RISE+` (номинал → дни подписки по курсу $1.99 = 30 дней, округление вниз).
- **Вывод в деньги отсутствует.** Ваучеры closed-loop (см. 14).

### 7.7. Команда (Squad)

- Один пользователь может состоять в **1 команде** в MVP (упрощение).
- Создатель = владелец, может исключать участников.
- Размер: до 8 человек (бесплатно до 4, до 8 — с RISE+ хотя бы у владельца). *Простой мотиватор подписки.*
- Инвайт: короткая ссылка `rise.app/j/{code}`, живёт 7 дней, при открытии — deep link в приложение (или на страницу установки с сохранением кода через deferred deep link, напр. Branch).
- Командный стрик: +1 за день, когда **все** участники выполнили подъём; обнуляется, если хоть один провалил (только если у него был будильник на этот день).

## 8. ПЛАТЕЖИ — ДЕТАЛЬНАЯ СПЕЦИФИКАЦИЯ

### 8.1. Модель денежной ставки: СПИСАНИЕ ПО ФАКТУ

**Никаких hold/преавторизаций в MVP.** Модель Forfeit/Beeminder:

1. Пользователь привязывает карту → Stripe `SetupIntent` (`usage: off_session`) → сохраняется `payment_method_id` и `stripe_customer_id`.
2. При создании будильника со ставкой — **деньги не списываются**, создаётся запись `stake` со статусом `pending`.
3. При `completed` → `stake.status = released`, списывается **только сервисный сбор** $0.30.
4. При `failed`/`expired` → сервер создаёт `PaymentIntent` (`off_session: true`, `confirm: true`) на сумму ставки + сбор.
5. Результат фиксируется в `transactions` и распределяется по долям (7.8).

### 8.2. Распределение списанной суммы

| Получатель | Доля | Куда идёт |
|---|---|---|
| Платформа | 50% | Выручка |
| Благотворительность | 30% | Обязательство перед эко-фондом (учёт в `impact_ledger`) |
| Reward Pool | 20% | Финансирование ваучеров |

- Доли хранятся в конфиге на сервере (`settings.stake_split`), **не хардкодить в клиенте**.
- Каждая транзакция создаёт 3 записи в `ledger_entries` — для прозрачной отчётности.

### 8.3. Сервисный сбор

- $0.30 фиксированно за активацию денежного режима (взимается при подтверждении будильника со ставкой, независимо от исхода — это плата за сервис, а не за результат).
- **Формулировка в UI строго:** «Сервисный сбор за обработку». Не «комиссия с выигрыша».
- 50% сбора → на деревья (маркетинговый смысл), 50% → платформа. Настраивается на сервере.

### 8.4. ⚠️ ПОДПИСКА — ТОЛЬКО ЧЕРЕЗ IAP

**Обязательно:** RISE+ — это цифровой контент/функции внутри приложения, значит по правилам Apple (3.1.1) и Google подписка **должна** продаваться через StoreKit / Google Play Billing. Продажа через Stripe = гарантированный бан.

- Комиссия сторов: 30% (15% для Small Business Program при выручке < $1M/год — **обязательно зарегистрироваться**).
- Продукты:
  - `rise_plus_monthly` — $1.99/мес, триал 7 дней
  - `rise_plus_yearly` — $14.99/год, триал 7 дней
- Валидация через RevenueCat или собственную проверку receipt/purchase token на сервере.
- Восстановление покупок — обязательная кнопка.

### 8.5. ⚠️ СТАВКИ ЧЕРЕЗ STRIPE — РИСК РЕВЬЮ

Ставка — это не цифровой товар, а **плата за реальную услугу подотчётности** (аналог: DietBet, StepBet, Forfeit — они годами работают со Stripe в App Store). Тем не менее:

- В App Review Notes честно описать механику и сослаться на прецеденты (StepBet, DietBet, Forfeit, Beeminder).
- Ставка **не даёт** никаких цифровых благ внутри приложения — это принципиально. За деньги пользователь не покупает контент/функции, а несёт финансовую ответственность за своё поведение.
- Ваучеры-награды — **не покупаются**, только зарабатываются.
- Подготовить fallback: если Apple откажет — денежные режимы отключаются флагом `feature_flags.money_modes = false` без перевыпуска приложения (remote config).

### 8.6. Обработка ошибок платежей

| Сценарий | Поведение |
|---|---|
| Карта отклонена при off-session списании | Retry ×3 (через 1ч, 24ч, 72ч). Уведомление пользователю. Денежные режимы блокируются до погашения. |
| Требуется 3DS (SCA, Европа) | `PaymentIntent` уходит в `requires_action` → push пользователю «Подтверди платёж» → открывается экран с 3DS-челленджем. |
| Возврат/чарджбек | Отменить начисленные из этой транзакции награды, пометить пользователя флагом для ручной проверки. |
| Пользователь удалил карту | Денежные режимы недоступны, существующие ставки переводятся в `free` с уведомлением. |

### 8.7. Обязательные экраны/тексты для платежей

- Перед первой ставкой — экран согласия: что будет списано, когда, куда пойдут деньги, как оспорить. Явное подтверждение чекбоксом.
- Квитанция после каждой операции (в приложении + email).
- История транзакций в настройках.
- Возможность отключить денежные режимы одним переключателем.

```sql
  created_at timestamptz not null default now()
);

-- ПОДПИСКИ
create table subscriptions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references profiles on delete cascade,
  platform text not null check (platform in ('ios','android')),
  product_id text not null,
  original_transaction_id text unique,
  status text not null check (status in ('trial','active','grace','expired','cancelled')),

  updated_at timestamptz not null default now()
);
```

**RLS обязательно:** пользователь видит только свои записи; записи команды — только участники команды; `ledger_entries`, `stakes` — read-only через SECURITY DEFINER функции, никаких прямых insert/update с клиента.

## 13. КАЧЕСТВО И ТЕСТИРОВАНИЕ

### 13.1. Обязательные тесты

- **Unit:** логика стрика (граничные случаи смены суток, TZ), распределение сумм (округление центов), генератор узоров/примеров, расчёт поинтов и множителя RISE+.
- **Integration:** полный цикл `alarm_run` (scheduled → completed / failed), Stripe-флоу в тестовом режиме (успешная карта `4242...`, отклонённая `4000000000000002`, требующая 3DS `4000002500003155`).
- **E2E (Detox/Maestro):** онбординг → создание будильника → симуляция срабатывания → прохождение испытания → победа → шеринг.
- **Ручные на реальных устройствах:** будильник при закрытом приложении, при заблокированном экране, в авиарежиме, при низком заряде, при включённом Focus/DND, после перезагрузки.

## 14. ЮРИДИЧЕСКИЕ РАМКИ — НЕ НАРУШАТЬ

Это не «пожелания», а рамки, определяющие законность продукта. Их нельзя менять без юриста.

### 14.1. Почему это не азартная игра

Формулировки, которые должны быть отражены в продукте и ToS:

1. **Исход зависит от дисциплины пользователя, а не от случая.** Нет элемента случайности.
2. **Деньги проигравшего не идут напрямую победителю.** Они уходят в обезличенный фонд платформы; награды выдаёт платформа из своего фонда.
3. **Награды нельзя обналичить.** Ваучеры closed-loop: только использование на покупки или обмен на функции внутри приложения.
4. **Плата позиционируется как сервисный сбор**, а не ставка на результат.
5. Ставки небольшие ($1–$10), количество ограничено (не более 1 денежного будильника в сутки).

Прецеденты для App Review и юристов: **StepBet, DietBet, Forfeit, Beeminder, HealthyWage** — работают в сторах годами с аналогичной моделью.

### 14.2. Что категорически запрещено в коде

- ❌ Вывод внутренних наград/баланса в реальные деньги.
- ❌ Прямой перевод средств от одного пользователя другому.
- ❌ Крипто-награды, крипто-ваучеры, любые ликвидные активы.
- ❌ Розыгрыши с платным участием.
- ❌ Формулировки «выиграй», «ставка», «джекпот», «казино», «bet» в UI и метаданных сторов. Использовать: «на кону», «сервисный сбор», «челлендж», «награда».

### 14.3. Оспаривание списаний (обязательно для доверия)

- Кнопка `Оспорить списание` на экране провала и в истории транзакций.
- Форма: причина (выпадающий список + текст), опционально прикрепить запись видео как доказательство.
- SLA рассмотрения: 72 часа.
- Первое оспаривание в течение 30 дней — **автоматическое одобрение** (политика доброй воли). Это резко снижает отток и негативные отзывы.
- Все решения логировать.

### 14.4. Приватность

- Политика конфиденциальности и ToS — обязательны, ссылки в профиле и при регистрации.
- Возраст 18+ для денежных режимов (подтверждение при активации).
- Видео: локально по умолчанию, явное согласие на загрузку, автоудаление.
- Контакты: не читать книгу целиком; инвайты через ссылки.
- GDPR/CCPA: экспорт данных и удаление аккаунта из приложения (требование сторов).
- App Privacy Nutrition Labels (iOS) и Data Safety (Android) — заполнить честно.

## 15. АНТИ-АБЬЮЗ И ГРАНИЧНЫЕ СЛУЧАИ

| Сценарий | Решение |
|---|---|
| Пользователь удаляет будильник перед срабатыванием, чтобы не платить | Блокировка изменений/удаления за 30 мин до срабатывания при денежном режиме |
| Переводит системное время назад | Всё окно считается по серверному времени; при отсутствии сети — сохранять локально и валидировать при первом коннекте |
| Отключает интернет на ночь | Испытание работает офлайн; результат отправляется при появлении сети; списание — по факту синхронизации |
| Удаляет приложение после провала | Списание всё равно проходит (off-session), уведомление по email |
| Просит друга пройти испытание за себя | В MVP не решаем (видео — доказательство при споре). В Фазе 2 — опциональная верификация другом |
| Накручивает рефералы | Награда за реферала начисляется только после того, как приглашённый **успешно завершил 3 подъёма** |
| Спамит «разбудить друга» | Rate limit: 1 нудж на человека в сутки |
| Множественные аккаунты ради ваучеров | Привязка к device ID + лимит наград на устройство |
| Смена часового пояса (перелёт) | Пересчитывать `next_fire_at` при смене TZ; уведомить пользователя: «Ты сменил часовой пояс. Будильник теперь в 7:00 по местному» |
| Телефон разрядился ночью | Честно: будильник не сработает. Показать предупреждение вечером, если заряд < 20%: «⚠️ Низкий заряд. Поставь на зарядку, иначе RISE не разбудит» |
